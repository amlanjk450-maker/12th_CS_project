PROJECT 2 — SCHOOL CANTEEN ORDERING SYSTEM
CLASS 12 COMPUTER SCIENCE FINAL PROJECT
Goal: Build a small local school-canteen ordering and billing system using Python + MySQL. It should look modern during demonstration but use simple, minimal, syllabus-friendly code.

TECH STACK
- Python 3
- MySQL
- mysql-connector-python
- Optional: Tkinter. Use it only if the interface can stay simple.
- No web development, APIs, payment gateways, or unnecessary libraries.

CORE IDEA
A student selects food items, adds them to a cart, confirms the order, and gets an automatically generated bill. The canteen can view orders and update their status.

MAIN FEATURES
1. Display Menu
   - Item ID
   - Item name
   - Category
   - Price
   - Availability

2. Place Order
   - Student name / ID
   - Select multiple menu items
   - Quantity
   - Calculate subtotal and total

3. Cart
   - Show selected items
   - Quantity
   - Item price
   - Line total

4. Generate Bill
   - Order ID
   - Student
   - Items
   - Quantity
   - Total amount
   - Order date/time

5. Order Status
   - Placed
   - Preparing
   - Ready
   - Collected

6. View Orders
7. Search/View Menu
8. Admin-style functions:
   - Add menu item
   - Update price
   - Change availability
   - Delete menu item

DATABASE
Use:
canteen_db

Tables:
1. menu
   - id INT PRIMARY KEY AUTO_INCREMENT
   - name VARCHAR(...)
   - category VARCHAR(...)
   - price DECIMAL(10,2)
   - available BOOLEAN

2. orders
   - id INT PRIMARY KEY AUTO_INCREMENT
   - student_name VARCHAR(...)
   - student_id VARCHAR(...)
   - order_date DATETIME
   - total DECIMAL(10,2)
   - status VARCHAR(...)

3. order_items
   - id INT PRIMARY KEY AUTO_INCREMENT
   - order_id INT
   - menu_id INT
   - quantity INT
   - price DECIMAL(10,2)

Use a foreign key for order_id and menu_id if practical.
Keep the design compact.

CODING CONSTRAINTS
- Aim for about 250–400 lines of Python.
- Keep everything easy to understand.
- Avoid classes if functions are enough.
- No authentication unless very simple.
- No online payment.
- No PDF generation unless it is almost free in terms of complexity.
- Use parameterized SQL.
- Validate quantity and numeric input.
- Handle unavailable menu items.
- Use one clear main menu.
- Avoid duplicated code by creating small helper functions.

POLISH FEATURES THAT ARE CHEAP TO IMPLEMENT
- Automatically generate order ID using MySQL AUTO_INCREMENT.
- Show current date/time.
- Prevent ordering unavailable items.
- Display the most recent order after checkout.
- Simple status update menu.

UI
Use a neat terminal interface if that keeps the code smaller.
Use Tkinter only when it materially improves the demonstration without adding lots of code.
